1. GENERIC  (tasarım kararı verildi, uygulanmadı)
------------------------------------------------------------------------------
Yazım:
    fonksiyon en_büyük<T>(l: Liste<T>) -> T { ... }
    fonksiyon deneme<T, Z>(x: T, y: Z) -> Tam veya Hata { ... }
    tür Kutu<T>(değer: T) { fonksiyon al() -> T { döndür değer } }
    ata k = Kutu(değer: 5)          // T kendiliğinden Tam(64)

Kurallar (kullanıcı kararı):
[ ] Tip parametresine KISIT YAZILMAZ (<T: Arayüz> yok). Tip isteyen zaten parametrede
    yazar: fonksiyon f(x: Tam).
[ ] "Kalıp tarzı": fonksiyon her çağrıldığı somut tiplerle AYRICA denetlenir ve ayrıca
    derlenir (monomorfizasyon; çalışma anında maliyet yok). Hata mesajı hem tanımdaki
    satırı hem çağrının satırını gösterir:
        HATA (dosya.kolay, satır 4): deneme içinde: Yazı ile Tam(64) toplanamaz.
        (çağrı: satır 12, T = Yazı, Z = Tam(64))
[ ] Tip parametreleri büyük harfle başlar; tek harf (T) ya da Türkçe ad (Eleman) serbest.
[ ] Tip, argümanlardan çıkarılır: en_büyük([1, 2]) -> T = Tam(64). Çıkarılamazsa açıkça:
    en_büyük<Tam(8)>(l)  (bu yazımın gerekip gerekmediği uygulanırken kullanıcıya sorulabilir)
[ ] Karşılaştırma kuralı: türde
        fonksiyon karşılaştır(diğer: Tür) -> Tam(8)     // -1, 0, 1
    varsa <, >, <=, >=, sırala(), sıralı(), en_büyük(), en_küçük() o türde de çalışır.
    Yoksa: "Kişi karşılaştırılamaz: türe 'karşılaştır(diğer: Kişi) -> Tam(8)' fonksiyonu ekleyin."
Uygulama notları:
[ ] check.rs: fonksiyon/tür bildirimine tip parametreleri (ast.rs FnDecl.generics, TurDecl.generics).
[ ] Gövde ilk geçişte denetlenmez; her farklı tip ataması için (T=Tam(64), ...) bir kopya
    FuncInfo oluşturulup denetlenir (önbellek: (fid, tipler) -> yeni fid).
[ ] Generic türler: Kutu<Tam(64)> ve Kutu<Yazı> ayrı TypeId'ler (ad: "Kutu<Tam(64)>").
[ ] REPL: fonksiyon anahtarına (TFunc.key) tip ataması da eklenmeli (yoksa hücreler arasında
    yanlış kopyaya eşlenir).

[?] GENERIC LAMBDA — SİSTEMİN NASIL OLACAĞI KULLANICIYA SORULACAK
    Bağlamı olmayan lambda generic olmalı:
        ata iki_kat = her x için x * 2
        yazdır(iki_kat(5), iki_kat(2.5))      // 10  5.0
    Şu an parametre tipi yazılmak zorunda: her (x: Tam(64)) için x * 2
    Uygulamaya başlamadan önce kullanıcıya sorulacak sorular:
      - Generic lambda bir değişkende saklanınca tipi ne olur? (yazdırılınca, :tip ile ne görünür)
      - Generic lambda bir listeye konabilir mi, başka bir fonksiyona verilebilir mi?
        (Somut tip istenen yere verilince orada somutlaşması önerilebilir.)
      - Aynı lambda iki farklı tiple çağrılınca iki kopya mı derlenir? (önerim: evet)
      - Generic lambda dışarıdan değişken yakalarsa yakalama kuralları aynı mı kalır?

2. HATA YÖNETİMİ  (kullanıcının tasarımı, uygulanmadı)
------------------------------------------------------------------------------
    fonksiyon böl(a: Tam(64), b: Tam(64)) -> Tam(64) veya Hata {
        eğer b == 0 { döndür Hata.SıfıraBölme(mesaj: "Bölen sıfır olamaz.") }
        döndür a / b
    }

    dene {
        yazdır(böl(100, oku().tama()))
    } yakala h: Hata.Dönüşüm {
        yazdır("Sayı yazmadınız:", h.mesaj)
    } yakala sayı: Tam {              // fırlatılan herhangi bir değer yakalanabilir
        yazdır(sayı)
    } yakala diğer {                  // tipsiz: geri kalan her şey
        yazdır(diğer)
    }

    dene { riskli_iş() }              // hatalar yok sayılır (derleyici uyarır)
    fırlat 42                         // herhangi bir değer fırlatılır

Kurallar (kullanıcı kararı, hepsi kabul edildi):
[ ] 1. Tek başına dene { } hatayı yok sayar; blok hatanın olduğu yerde durur, program
       bloğun sonrasından devam eder; derleyici uyarır:
       "Uyarı: 'dene' bloğundaki hatalar yok sayılıyor (satır 3: deneme() hata verebilir)."
[ ] 2. yakala ad: Tip yazımı. eşleştir'de de "n: Tam ->" yazımı geçerli olur (eski Tam(n) da kalır).
[ ] 3. fırlat değer: HER değer fırlatılabilir ve tipine göre yakalanır. Tipsiz "yakala ad"
       geri kalan her şeyi yakalar; tipi, o blokta fırlatılabilen tiplerin 'veya'sıdır
       (derleyici tüm programı gördüğü için çıkarır). Hiç fırlatılamayan tip için uyarı:
       "Uyarı: bu blokta Ondalık fırlatılamaz, 'yakala o: Ondalık' dalı hiç çalışmaz."
       (Lambda ve C fonksiyonlarında derleyici "her şey fırlatılabilir" varsayar.)
[ ] 4. Hazır hatalar Hata.X nesneleridir ve yakalanabilir:
         Hata.SıfıraBölme   x / 0
         Hata.İndeks        liste sınırı aşıldı
         Hata.Anahtar       sözlükte anahtar yok
         Hata.Taşma         Tam(8) taştı
         Hata.Dönüşüm       "abc".tama(), olarak sığmadı
         Hata.Dosya         (dosya işlemleri gelince)
       Her hatanın "mesaj" alanı vardır, satır bilgisi kendiliğinden gelir.
       Kendi hatalar: tür GeçersizYaş[Hata](yaş: Tam)  -> yakala h: GeçersizYaş { h.yaş }
       Yakala dalları özelden genele; ters sırada uyarı:
       "Uyarı: 'yakala z: Hata' önce geldiği için 'Hata.SıfıraBölme' dalı hiç çalışmaz."
       "Çok derin özyineleme" derlenmiş programda yakalanamaz (yığın taşmış olur).
[ ] 5. "-> T veya Hata" döndüren çağrı dene içinde kullanılırsa dönen Hata kendiliğinden
       fırlatılır; dene dışında eşleştir ile değer olarak ele alınır. dene dışında T gibi
       kullanılırsa derleme hatası:
       "'deneme()' hata verebilir (Tam(64) veya Hata). Bir 'dene { } yakala' bloğu içinde
        kullanın ya da eşleştir ile kontrol edin."
[ ] 6. Yakalanmayan değer: "ÇALIŞMA HATASI: Yakalanmamış değer fırlatıldı: -5 (Tam(64))."
[ ] Hazır metotlar: tama(), ondalığa(), oku() vb. "T veya Hata" döndürür (önceki K1 kararı).
    Mevcut testler buna göre güncellenmeli. Liste boşken en_büyük()/en_küçük() da
    Hata fırlatmalı (şu an çalışma hatası).
Uygulama notları:
[ ] Yorumlayıcı: RtErr yerine fırlatılan değer (Value) taşıyan Unwind; dene blokları onu yakalar.
[ ] Derleyici: dene girişinde atlama noktası (setjmp benzeri); kolay_hata ve fırlat oraya
    atlar. Maliyet sadece dene bloğuna girişte. Atlanan geçici nesnelerin belleği geri
    verilmeyebilir (sadece hata anında, küçük sızıntı).
[ ] Hata türü hazır bir 'tür' olarak (mesaj: Yazı) ve alt türleri program başında tanımlı.

3. WINDOWS VE macOS DESTEĞİ
------------------------------------------------------------------------------
Şu an sadece Linux. Bu makinede sadece Linux var: macOS/Windows kodu yazılabilir ama
burada çalıştırılıp doğrulanamaz (Windows için mingw ile en fazla çapraz derleme denenebilir).

Değişmesi gerekenler:
[ ] Yorumlayıcı (Rust): az değişiklik.
    - main.rs / repl.rs: signal(SIGINT) -> Windows'ta SetConsoleCtrlHandler.
    - repl.rs: geçmiş dosyası yolu (%APPDATA%\kolay, ~/Library/Caches/kolay).
    - kur.sh yerine Windows için kurulum (PowerShell betiği ya da cargo install).
[ ] Dış kütüphaneler (dis.rs):
    - macOS: dlopen aynı; ad adayları .dylib (libm.dylib), /usr/lib, /opt/homebrew/lib.
    - Windows: LoadLibraryW / GetProcAddress; ad adayları m.dll, msvcrt.dll, ucrtbase.dll.
    - libffi: macOS'ta Homebrew/sistem; Windows'ta libffi paketlenmeli (ya da libffi-sys crate'i).
[ ] Derleyici çalışma kütüphanesi (runtime/*.c):
    - cekirdek.c: pthread + sigaltstack + ucontext (derin özyineleme yakalama) ->
      macOS: aynı API, register adı farklı (uc_mcontext->__ss.__rip / __pc);
      Windows: iş parçacığı için _beginthreadex/CreateThread, yığın taşması için
      AddVectoredExceptionHandler (EXCEPTION_STACK_OVERFLOW).
    - __start_kolay_kod / __stop_kolay_kod (ELF bölüm sınırları) ->
      macOS: section$start$__TEXT$kolay_kod; Windows: .text$ sıralı bölümler ya da tablo.
    - memmem (GNU): macOS'ta var; Windows'ta kendi sürümü yazılmalı.
    - _Float16, __int128: clang'da var (MSVC'de yok -> Windows'ta clang zorunlu).
    - isatty/setvbuf/signal: Windows'ta _isatty, SetConsoleCtrlHandler.
[ ] codegen/mod.rs: bağlama komutları (-lm -lpthread Linux'a özel), çıktı adı (.exe),
    geçici klasör, llvm-link bulunamazsa nesne dosyası yolu.
[ ] VS Code eklentisi: F5 komutundaki tırnaklama (PowerShell), kolay.yol ayarı.
[ ] Test çalıştırıcı (testler/calistir.sh): Windows için ayrı ya da Rust ile yazılmış bir çalıştırıcı.
[?] GitHub Actions ile üç sistemde otomatik test: bir GitHub deposu gerekiyor (şu an depo yerel).
Önerilen sıra: önce macOS (POSIX'e yakın), sonra Windows.

2. HATA YÖNETİMİ  (kullanıcının tasarımı; UYGULANDI 2026-10-24, yorumlayıcı + derleyici)
------------------------------------------------------------------------------
    fonksiyon böl(a: Tam(64), b: Tam(64)) -> Tam(64) veya Hata {
        eğer b == 0 { döndür Hata.SıfıraBölme(mesaj: "Bölen sıfır olamaz.") }
        döndür a / b
    }

    dene {
        yazdır(böl(100, oku().tama()))
    } yakala h: Hata.Dönüşüm {
        yazdır("Sayı yazmadınız:", h.mesaj)
    } yakala sayı: Tam {              // fırlatılan herhangi bir değer yakalanabilir
        yazdır(sayı)
    } yakala diğer {                  // tipsiz: geri kalan her şey
        yazdır(diğer)
    }

    dene { riskli_iş() }              // hatalar yok sayılır (derleyici uyarır)
    fırlat 42                         // herhangi bir değer fırlatılır

Kurallar (kullanıcı kararı, hepsi kabul edildi):
[x] 1. Tek başına dene { } hatayı yok sayar; blok hatanın olduğu yerde durur, program
       bloğun sonrasından devam eder; derleyici uyarır:
       "Uyarı: 'dene' bloğundaki hatalar yok sayılıyor (satır 3: deneme() hata verebilir)."
[x] 2. yakala ad: Tip yazımı. eşleştir'de de "n: Tam ->" yazımı geçerli olur (eski Tam(n) da kalır).
[x] 3. fırlat değer: HER değer fırlatılabilir ve tipine göre yakalanır. Tipsiz "yakala ad"
       geri kalan her şeyi yakalar; tipi, o blokta fırlatılabilen tiplerin 'veya'sıdır
       (derleyici tüm programı gördüğü için çıkarır). Hiç fırlatılamayan tip için uyarı:
       "Uyarı: bu blokta Ondalık fırlatılamaz, 'yakala o: Ondalık' dalı hiç çalışmaz."

[x] 4. Hazır hatalar Hata.X nesneleridir ve yakalanabilir:
         Hata.SıfıraBölme   x / 0

3. WINDOWS VE macOS DESTEĞİ
------------------------------------------------------------------------------
Şu an sadece Linux. Bu makinede sadece Linux var: macOS/Windows kodu yazılabilir ama
burada çalıştırılıp doğrulanamaz (Windows için mingw ile en fazla çapraz derleme denenebilir).

Değişmesi gerekenler:
[ ] Yorumlayıcı (Rust): az değişiklik.
    - main.rs / repl.rs: signal(SIGINT) -> Windows'ta SetConsoleCtrlHandler.
    - repl.rs: geçmiş dosyası yolu (%APPDATA%\kolay, ~/Library/Caches/kolay).
    - kur.sh yerine Windows için kurulum (PowerShell betiği ya da cargo install).
[ ] Dış kütüphaneler (dis.rs):
    - macOS: dlopen aynı; ad adayları .dylib (libm.dylib), /usr/lib, /opt/homebrew/lib.
    - Windows: LoadLibraryW / GetProcAddress; ad adayları m.dll, msvcrt.dll, ucrtbase.dll.
    - libffi: macOS'ta Homebrew/sistem; Windows'ta libffi paketlenmeli (ya da libffi-sys crate'i).
[ ] Derleyici çalışma kütüphanesi (runtime/*.c):
    - cekirdek.c: pthread + sigaltstack + ucontext (derin özyineleme yakalama) ->
      macOS: aynı API, register adı farklı (uc_mcontext->__ss.__rip / __pc);
      Windows: iş parçacığı için _beginthreadex/CreateThread, yığın taşması için
      AddVectoredExceptionHandler (EXCEPTION_STACK_OVERFLOW).
    - __start_kolay_kod / __stop_kolay_kod (ELF bölüm sınırları) ->
      macOS: section$start$__TEXT$kolay_kod; Windows: .text$ sıralı bölümler ya da tablo.
    - memmem (GNU): macOS'ta var; Windows'ta kendi sürümü yazılmalı.
    - _Float16, __int128: clang'da var (MSVC'de yok -> Windows'ta clang zorunlu).
    - isatty/setvbuf/signal: Windows'ta _isatty, SetConsoleCtrlHandler.
[ ] codegen/mod.rs: bağlama komutları (-lm -lpthread Linux'a özel), çıktı adı (.exe),
    geçici klasör, llvm-link bulunamazsa nesne dosyası yolu.
[ ] VS Code eklentisi: F5 komutundaki tırnaklama (PowerShell), kolay.yol ayarı.
[ ] Test çalıştırıcı (testler/calistir.sh): Windows için ayrı ya da Rust ile yazılmış bir çalıştırıcı.
[?] GitHub Actions ile üç sistemde otomatik test: bir GitHub deposu gerekiyor (şu an depo yerel).
Önerilen sıra: önce macOS (POSIX'e yakın), sonra Windows.
